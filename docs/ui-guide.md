# Web UI 使用指南（本機模擬器）

這個 Web UI 只是現有 Python 引擎的「臉」：所有數字都由 `src/marketplace_sim/` 的引擎與控制平面計算，前端只負責呈現和操作。
同一套前端有兩種資料來源：

| 模式 | 資料從哪來 | 能做什麼 | 用在哪 |
|---|---|---|---|
| **Demo（靜態）** | `frontend/public/demo/*.json`：用 **synthetic（虛構）** 參數包預先算好的結果 | 只能檢視。可以看預設方案、範本情境和預算好的壓力測試；修改後的內容需要本機引擎 | 公開展示（GitHub Pages，**目前不要發布**，見最後一節） |
| **實戰（本機 API）** | 本機的 FastAPI（`127.0.0.1:8765`）即時呼叫引擎，可以載入你的 private 參數包 | 全部功能：送出決策推進、即時比較、編輯並執行情境與 sweep、切換參數包 | 只在自己的電腦上用 |

畫面右上角一定會標出目前的參數包：綠色 **SYNTHETIC 虛構資料**，或閃爍的紅色 **PRIVATE 真實資料**。同時也會標出目前是哪個模式。

## 0. 三個一鍵腳本（Windows，雙擊即可）

放在 `tools\bat\`。它們是本機工具，**不在 repo 裡**（`tools/` 整個被 git 忽略），所以新 clone 不會有，需要從原本的電腦複製過去。
三個腳本都會自己從所在位置推算 repo 根目錄，搬移資料夾後仍可使用；出錯時會印出中文說明並停住視窗。

| 腳本 | 做什麼 | 什麼時候點 |
|---|---|---|
| `setup-once.bat` | 安裝 git pre-push hook（每次 push 前逐一檢查 commit），並確認 hook 確實存在。前端相依沒裝就依 `package-lock.json` 安裝一次。最後查詢 GitHub 上的 repo 是 public 還是 private；是 public 就印出大字警告。 | **只需要一次**：新電腦、重新 clone、或搬移 repo 資料夾之後（hook 記錄了 Python 的路徑） |
| `start-ui.bat` | 啟動前會檢查 Python、API 模組、Node、前端相依與 private 參數包。接著同時啟動本機 API（private 參數包）與 live 模式前端，並打開瀏覽器。按 Enter 或直接關閉視窗，兩者都會一起停止。 | **每天用**：要用真實資料試算、比較方案時。加 `-Synthetic` 改用虛構資料練習 |
| `backup-private.bat` | 把整個 `evidence\private\` 複製到備份位置（包含外洩留存 `leak-archive\` 與完整歷史 bundle）。複製後比對檔案數、總大小與每個檔案的大小。只複製，不刪除來源。目的地若在 repo 內部或任何含 `.git` 的資料夾裡，會直接拒絕。 | 每次有重要的新私有資料後，以及**清除 git 歷史之前**。預設存到同磁碟機的 `\tools\backup\simulation_HW\<日期時間>\`；建議指定外接硬碟，例如 `backup-private.bat E:\backup`。要放雲端時用 `--cloud`（見下方） |

### 雲端暫存：`backup-private.bat --cloud`

想在私人 Google Drive 也留一份時使用。**腳本只準備檔案，不會上傳；上傳一律由你手動進行。**

1. 執行 `backup-private.bat --cloud`。備份會放在固定、好找的暫存區：同磁碟機的 `\tools\cloud-staging\simulation_HW\<日期時間>\`。要改用別的暫存區，就加上路徑，例如 `backup-private.bat --cloud F:\stage`。
2. 複製並校驗後，腳本會再做兩件事：
   * 在備份資料夾裡寫一份 `READ-ME-BEFORE-UPLOAD.txt`，說明內容與上傳規則；
   * 把整個資料夾打包成旁邊的 `<日期時間>.zip`，並校驗 zip 內的檔案數與每個檔案的大小。打包不會刪除資料夾。
3. 視窗會印出資料夾與 zip 的完整路徑。把**其中一個**手動拖進你的**私人** Google Drive。
4. 上傳後在 Drive 對它按「共用」確認：
   * 只有你自己，沒有共用給別人；
   * 不在共用資料夾或共用雲端硬碟裡；
   * 「一般存取權」是「限制」，不是「知道連結的任何人」。

> [!CAUTION]
> 這份備份含真實數值與從遊戲擷取的內容，也是將來清除 git 歷史後，唯一保有外洩原始內容的副本之一。
> * 只能放在**私人** Google Drive：不可公開、不可產生分享連結、不可放共用資料夾。
> * **絕對不可推到 GitHub** 或任何公開位置。
> * 上傳完成後，暫存區（`\tools\cloud-staging\`）可以自行刪除；另外保留一份外接硬碟的離線備份。

> [!IMPORTANT]
> * `start-ui.bat` 開的是實戰模式。畫面上帶 [L] 或 [P] 標記（「未校準 · 非預測」）的銷量、營收、市佔、利潤**不是預測**；只有標 [V] 的成本面數字可信。
> * `backup-private.bat` 的備份是將來清除 git 歷史後，唯一保有外洩原始內容的副本。請放在外接硬碟或其他實體位置，不要放進雲端同步資料夾或任何 repo。
> * `setup-once.bat` 查詢 repo 是否公開時，會向 GitHub 發一次不帶憑證的唯讀請求。

## 1. 啟動 Demo 模式

```powershell
# 一次做完：匯出 synthetic 結果 → 前端測試 → 建置 → 用 publication gate 檢查 dist/
python scripts\build_demo.py            # 加 --base /simulation_HW/ 可模擬 GitHub Pages 的路徑
cd frontend
npm run preview                          # 開 http://127.0.0.1:4173
```

開發時也可以直接執行 `cd frontend; npm run dev`（預設就是 Demo 模式，讀 `public/demo`）。

## 2. 啟動實戰模式

一鍵啟動：雙擊 `tools\bat\start-ui.bat`（見第 0 節）。它是下面這個 PowerShell 腳本的外殼，兩者都是本機腳本，**不在 repo 裡**：

```powershell
powershell -ExecutionPolicy Bypass -File tools\live\start_ui.ps1                 # 載入 private 參數包
powershell -ExecutionPolicy Bypass -File tools\live\start_ui.ps1 -Save <存檔路徑> # 接續某個私有存檔
powershell -ExecutionPolicy Bypass -File tools\live\start_ui.ps1 -Synthetic      # 用虛構參數練習
```

腳本會同時啟動本機 API 與 Vite 開發伺服器（live 模式），兩者都回應後才開啟瀏覽器。按 Enter 或關閉視窗，兩者會一起停止。加 `-NoBrowser` 則不開瀏覽器。

也可以手動在兩個終端機分別執行：

```powershell
.\.venv\Scripts\python.exe -m marketplace_sim.api --pack private      # 或 --pack synthetic、--save <存檔>
cd frontend; npm run dev:api                                           # 開 http://127.0.0.1:5173
```

* API **只會綁定 127.0.0.1**；指定其他位址會被拒絕。
* 任何 URL 都可以加 `?source=api` 或 `?source=static` 來強制指定資料來源。

## 3. 切換參數包

* 實戰模式：用右上角的「載入 synthetic」「載入 private」按鈕切換。切換後，所有畫面會重新讀取資料。
* private 參數包必須放在名為 `private` 的資料夾底下，否則 API 會拒絕載入。
* API 對每一個回應都標出 `is_private`；畫面依此顯示紅色警示橫幅。

## 4. 七個分析畫面（加上第 8 個入口：遊戲模式）

導覽列的第 8 項「遊戲模式」是另一種玩法，說明見[第 6a 節](#6a-遊戲模式一季--一回合)。下面七個分析畫面都保留不變。

| 畫面 | 內容 |
|---|---|
| 總覽 | 目前參數包、公司狀態、逐季趨勢圖（虛線代表未校準的數列）、最近一季的完整報表 |
| 決策編輯 | 從預設方案開始，用表單修改，可以「試算（不推進）」或「送出並推進一季」。送出只在實戰模式可用 |
| 方案比較 | 從同一狀態並排比較多個方案：與第一個方案不同的格子有色條，有差異的整列加深底色 |
| 情境工作台 | 編輯參數覆寫、事件與對手設定後執行；逐季結果中，有事件的季別以 ⚑ 標記 |
| 壓力測試 | 執行或讀取 sweep，列出最差 N 個情境與各變數的敏感度。**頁首常駐橫幅**提醒結果反映文獻假設 |
| 參數 diff | 比較兩個參數包；已驗證模組的參數有變動時整列標紅，並列出紅旗。真實參數包之間的比較不顯示數值 |
| 來源等級說明 | 圖例、每個等級的意義、「未校準 · 非預測」標記的說明，以及每個指標的公式、上游與證據 |

## 5. 來源等級怎麼看

順序：**verified（已驗證）> derived（推導）> estimated（估計）> literature（文獻）> placeholder（佔位）**。

* 數字的**顏色**和旁邊的**字母**代表等級：V、D、E、L、P。
* 上游只要含 literature 或 placeholder，數字旁就會出現斜紋的 **「未校準 · 非預測」** 標記，數字本身也加上點狀底線。
* 把滑鼠移到數字上（或用 Tab 鍵聚焦）會出現**來源鏈**：
  * 產生這個數字的規則；
  * 從這個項目往上游的每一步，各自的等級、公式與證據文件。
* 組合出來的數字一律取上游**最弱**的等級，不會標得比來源更強。

## 6. 為什麼現在的銷量、市佔、營收不能當預測

* 需求面目前是 **literature** 等級：函數形式來自公開的行銷與經濟學文獻（見 `docs/demand-literature.md`），係數是文獻中間值或標註的預設值，沒有用本局資料校準過（見 `docs/demand-model-spec.md`）。
* 利潤、稅與現金還受到 **placeholder** 的成本規則影響（生產成本、稅），所以這些數字也一樣帶有標記。
* 這些數字適合用來比較方案之間的方向與敏感度，不適合當作本局的預測值。
* 只有當需求面板累積足夠資料、擬合結果通過留出季驗證後，需求才會升為 **estimated**。
* 在那之前，壓力測試的「最差情境」反映的是文獻假設，不是本局預測。

## 6a. 遊戲模式（一季 = 一回合）

遊戲模式用回合制介面操作同一個引擎：每一季做產品、鋪貨、定價，先試算，再結束這一季，然後看結算卡。所有數字都由本機引擎計算，瀏覽器只負責顯示與操作。

### 怎麼進入

* 點導覽列的「8 遊戲模式」。
* **實戰（本機 API）**：用 `tools\bat\start-ui.bat` 啟動後就能自由操作。開局時可以選資料源：
  * **synthetic**：虛構資料，用來練習；
  * **private**：你的真實參數。
* **Demo（GitHub Pages / 靜態）**：只能重播一局預先算好的遊戲（synthetic 資料、3 個對手）。控制項都是唯讀，每按一次「結束這一季」就前進一季。
* 畫面最上方的狀態列一定會標出目前用的是 **SYNTHETIC 虛構資料**還是 **PRIVATE 實戰資料**。

### 開局設定

| 項目 | 說明 |
|---|---|
| 資料源 | synthetic 或 private（private 只能在本機 API 模式使用） |
| 對手數量 | 1 到 6 個，用滑桿選擇 |
| 每個對手的難度 | 對應現有的 bot 參數，**不是新的 AI**（見下表） |
| 用真實對手（replay） | 已預留。要有 private 資料，而且 `evidence/private/model/demand_panel/replay.json` 至少涵蓋兩季（Q2 起）並包含目前這一季，才能勾選；否則反灰並說明原因 |
| 起始方案 | 沿用預設方案清單，可把產品與鋪貨帶進第一季；也可以從零開始 |
| 目標 | 一句話，例如「讓期末現金最大化」；可以從預設帶入，也可以自己寫。目標會一直顯示在畫面底部的狀態列 |

| 難度 | 對應的 bot |
|---|---|
| 保守 | BaselineBot（每個區隔一個固定報價：平均願付價格的 90%，廣告固定），價格再 × 1.10 |
| 普通 | BaselineBot 原樣 |
| 激進 | RandomBot（報價為願付價格的 75–105%，廣告 0–60k，隨機鋪貨），價格再 × 0.85 |

### 畫面長什麼樣子

預設畫面只放「看得懂」的東西，細節都要點一下才展開：

| 位置 | 內容 |
|---|---|
| 最上方一條 | 資料源（**SYNTHETIC 虛構資料**／**PRIVATE 實戰資料**）、對手（圓點：實心深色＝激進、外框＝普通、虛線框＝保守）、已打完各季的成績單（Q1、Q2…），以及右邊的「顯示所有來源等級」開關 |
| 中央：城市地圖 | 等角視角的示意地圖（不是真實地理）。每個區域是一塊地，每個城市是一塊地皮；工廠在自己的一小塊地上，網路中心是一座電塔 |
| 地圖下方：自行車卡 | 每個產品一張卡：一台自行車（車架顏色代表類型）、名稱、定價，以及一條「定價／成本／願付價格」指示條 |
| 右側：側欄 | 點地圖上的城市、電塔、工廠，或卡片上的「調整」、底部的「試算」時才出現；按 × 或 Esc 關閉 |
| 最下方：狀態列 | 第幾季、現金、產能、目標，以及「試算這一季（不推進）」和「結束這一季」兩個按鈕 |

地圖上的地皮有三種樣子：

* **亮燈的建築**：已經營業的店面或網路中心。
* **虛線的透明建築**：本季要開設的（按了「本季在這裡開店」之後立刻出現）。工廠旁出現虛線建築，表示本季要擴充產能。
* **暗色空地加幾棵樹**：還沒開設。

### 每一回合

1. **鋪貨**：點地圖上的城市，側欄會顯示：
   * 這裡各客群的一年市場規模和願付價格；
   * 開店成本（可信，直接顯示）和每季租金（預估，帶 ≈）；
   * 「本季在這裡開店」按鈕。新開的店從下一季開始銷售。
   * 點電塔可以開設該區的網路中心（涵蓋整個區域）。
2. **工廠**：點地圖上的工廠，選擇要擴充多少產能。本季買的產能，下季才能用。
3. **做產品**：按「＋ 新增自行車」，或卡片上的「調整」，側欄會打開這台車的設定：
   * 價格、生產量、廣告三個滑桿；每次調整，引擎都會自動試算一次（不推進），卡片上的指示條跟著更新。
   * 類型和配置（Core kit、Body、Finish 等）從資料源讀取，換成別的商品只要換資料。
   * 產品第一次設計後，類型與配置就會鎖定，因為引擎沿用第一次的設計。
   * 生產量的上限是本季產能。
4. **試算這一季（不推進）**：側欄顯示這一季的關鍵結果，「完整明細」裡有引擎回傳的每一行。不會改變遊戲狀態，可以反覆修改再試算。
5. **結束這一季**：真正推進一季，並翻出**成績單**：
   * 左邊是市佔長條圖：「我們」是青綠色，每個對手是灰色，每條旁邊直接標百分比；
   * 右邊是本季結果：各產品銷量、營收、淨利、期末現金，以及本季的投資（產能、開店等）；
   * 下方一行總說明，交代哪些數字是預估、什麼時候變實際；
   * 「完整明細」展開後是全部數字（投資與費用、銷售與市佔、損益與現金）和引擎的提醒。
6. 上方的 **Q1、Q2…** 可以重新打開那一季的成績單。

### 自行車卡上的指示條

* **綠色區段**：這台車的目標客群在各城市的願付價格範圍（資料源公布的值）。
* **灰色細線**：引擎試算出的單位成本（目前是預估）。
* **圓點**：你的定價。

指示條只是把這三個值畫在同一條線上，不計算毛利或任何新的數字。

### 「預估」與「實際」是什麼意思

* **直接顯示的數字（可信）**：等級是 verified 或 derived，不加任何標記。例如開店成本、網路中心開設成本、產能投資、每季產能、CD 利息、廣告支出，以及各城市的市場規模和願付價格。
* **前面有灰色小 ≈ 的數字（預估）**：等級是 literature 或 placeholder。滑鼠移上去或用鍵盤聚焦時，會顯示「預估 · Q2 校準後變實際」或「預估 · 成本規則驗證後變實際」。
  * **literature**：需求面，例如銷量、需求量、市佔、營收、市場總量、對手的銷量與市佔。函數形式來自公開文獻，係數沒有用本局資料校準。
  * **placeholder**：尚未驗證的成本規則，例如單位成本、生產成本、設計費、租金、稅，以及受它們影響的利潤與期末現金。
* 注意：單位成本目前是 **placeholder**，所以自行車卡上的成本也帶 ≈。只有開店、網路中心、產能投資這類已驗證的成本會直接顯示。
* **「顯示所有來源等級」開關**（預設關）：打開後，每個數字都改回分析畫面那種完整標記（V/D/E/L/P 字母、「未校準 · 非預測」標籤和來源鏈），給進階使用者和除錯用。這個選擇只記在你自己的瀏覽器裡。
* 市佔在遊戲畫面以百分比顯示；打開開關後顯示引擎原始的 0–1 比例。
* 來源等級由引擎與 API 決定，遊戲畫面只改變「怎麼呈現」，判定方式和第 7 個畫面「來源等級說明」完全相同。

### 什麼時候預估會變成實際

* **銷量、營收、市佔（literature）**：Q2 起累積本局的市場與對手資料，擬合需求模型。擬合結果要通過留出季驗證（MAPE ≤ 20%、方向命中率 ≥ 70%），需求才會升為 **estimated [E]**。之後這些數字會直接顯示，不再是預估。
* **單位成本、稅、租金（placeholder）**：完成對應的驗證實驗、殘差為 0 之後，才會升為 verified。
* 利潤與期末現金取上游**最弱**的等級，所以要等兩邊都驗證後才會變成實際。

## 7. 公開與私有的邊界

| 可以進 repo、可以上 Pages | 不進 repo、不進 build、不上 Pages |
|---|---|
| 前端原始碼（`frontend/src`）、設定檔、`frontend/public/demo` 中的 synthetic 匯出、建置腳本、GitHub Actions 設定 | private 參數包、真實結果、任何真實數值、`tools/` 下的啟動腳本、`frontend/dist`（由 CI 從已提交的內容重建） |

* 匯出 demo 只會使用 synthetic 參數包；只要有任何結果來自 private 參數包，或含本機絕對路徑，就拒絕匯出。
* publication gate 會檢查：
  * 前端原始碼與 demo 匯出檔（真實數值、私有標記、本機路徑）；
  * `--require-dist` 時的 `frontend/dist` 建置產物（真實數列、私有標記、本機路徑、不允許的檔案類型）。

## 8. 發布到 GitHub Pages（目前不要做）

> [!CAUTION]
> git 歷史中仍有真實數值（見 `docs/history-cleanup-plan.md` 與置頂待辦 `docs/TODO-history-cleanup.md`）。**歷史清除完成並驗證之前，不要發布 Pages，repo 也不要改回 public。**

完成清除之後的發布方式：
1. 在 GitHub 的 Settings → Pages，把 Source 設為 **GitHub Actions**。
2. 在本機執行 `python scripts\build_demo.py --base /simulation_HW/`，確認 gate 通過，再提交最新的 `frontend/public/demo`。
3. 在 GitHub 的 Actions 頁面手動執行 **demo-pages** workflow，並輸入確認文字 `PUBLISH-SYNTHETIC-DEMO`。

`docs/TODO-history-cleanup.md` 標示為 `CLEANED` 之前，這個 workflow 的第一步（`scripts/history_guard.py --action pages --strict`）會讓它直接失敗；本機的 `build_demo.py` 也會響鈴提醒，但不會擋住建置。

這個 workflow 只會建置已提交的原始碼與 synthetic 匯出，而且只能手動觸發（CI 上沒有私有資料可比對，所以真實值的檢查要在本機做）。
